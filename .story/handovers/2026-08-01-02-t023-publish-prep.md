## Four things worth knowing that the code cannot tell you

1. **Yarn resolves ccusage into its GLOBAL cache, inside a zip** (`~/.yarn/berry/cache/ccusage-npm-20.0.19-<hash>.zip/node_modules/ccusage/src/cli.js`). The obvious matrix assertion — "the resolved path is under the install prefix" — would have *failed a perfectly good install*. The matrix asserts package identity instead, which is layout-independent.
2. **Under yarn PnP a real invocation only works when the loader reaches the CHILD via `NODE_OPTIONS`.** Measured three ways in one prefix: `yarn spendbar alltime` works; `node --require .pnp.cjs … run.mjs alltime` FAILS, because argv flags do not propagate to children and spendbar spawns `node <shim-inside-zip>`; `NODE_OPTIONS="--require .pnp.cjs --loader .pnp.loader.mjs" node run.mjs alltime` works with a Node-only PATH and no yarn present. That is *why* `yarn spendbar` works, and it is what lets the matrix test yarn with no yarn on PATH.
3. **A literally node-only PATH breaks pnpm's own `.bin` shim**, which shells out to `sed`, `dirname` and `uname`. The child PATH is therefore node-only plus `/usr/bin:/bin`, and the claim is kept honest by the probe *enumerating PATH from inside the child* and failing if any package manager is reachable — measured, not assumed.
4. **The tarball legitimately ships `/Users/testuser` and a synthetic UUID** (ISS-005 scrub artifacts). Raw greps for `/Users/` or the UUID pattern can never pass; the contract's semantic classifiers are the real rule.

## ISS-018 — designed, deliberately not built

I did the hard part and stopped before the code, because a partially-correct committed oracle artifact set is worse than none: everything Python-free downstream would trust it. **The full design is in the ISS-018 impact field** — read that first, do not re-derive it. Highlights:

- **The authored invocation inventory**, read out of `usage.py` rather than discovered by instrumentation (which is what the design demands, since instrumenting only finds argv for whatever you happened to run). Five argv shapes, plus a per-command call table. **Three entries would be got wrong by guessing:** `compare` issues ONE instances call spanning both days rather than one per day; `codex_sessions` is always passed `until=None` deliberately (`usage.py:334-336`); and `codex_daily` is called *unconditionally* at `usage.py:360` even though its output is only displayed for windowed runs.
- **Canonical rendering is simpler than the original plan assumed.** `fake_ccusage.py:13` derives `HOME_ENC` from `expanduser("~")` at import, and expanduser only reads `$HOME` without requiring the path to exist — so generating under `HOME=/fixture/home` produces canonical payloads *directly*. Post-hoc substitution is a verifier-only concern. This is also a **privacy gate**, not just determinism: these artifacts get committed to a repo about to go public, so a generator that forgets the canonical env commits the maintainer's home path. Add a test for that.
