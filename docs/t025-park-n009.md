## Park reason 1 — the exact-key schema cannot be completed while surface 6 is undecided (ISS-090)

N-009 §1 fixes the surface key set **per SCHEMA_VERSION** and requires `sourceVersion` and the
payload to validate against it by **exact set equality**. Surface 6, `claude-transcript-hours`, is
defined as "the facts `transcripts.ts` derives today". Verified against the code, one all-time pass
cannot derive those facts:

- `transcripts.ts:126` applies a per-file **mtime filter keyed on the target date**, so the surviving
  file set is date-dependent.
- `transcripts.ts:171` runs the `[requestId, message.id]` **dedupe BEFORE** the record's own date is
  tested at `:178`, and `seen` is per-invocation.

Compounded: a date-dependent file set makes `seen` date-dependent, which makes duplicate winners
date-dependent. One global pass cannot reproduce 190 per-date passes, and the difference is not a
fixed offset. Storing enough to re-derive it means per-record state for the whole corpus. 190 real
passes cost ~100 minutes (measured: one pass is **31.4 s** over 5.98 GiB / 14 232 files).

**My workaround was refuted.** Revision 2 specified five surfaces and called the sixth "a one-line
registry edit later". Round 2 showed that is wrong: omitting the key creates an **unauthorized
five-surface schema**; retaining it leaves candidates, validation, watermarks and tests
unconstructible; and adding it later needs a `SCHEMA_VERSION`/store-root change plus every exact-set
fixture and producer updated. The schema is not divisible the way I claimed.

## Park reason 2 — no witnessable disappearance policy exists for claude-blocks (ISS-091)

N-009 §3 requires every surface to declare one. Two attempts died in two rounds:

1. **A declared retention horizon (30 d)** — rejected round 1: it permits real rows to vanish the day
   after the constant on no evidence the producer prunes then, and the volume cap meant to bound it
   was **per-publish resettable**, so repeated individually-legal losses erode everything while every
   transition passes.
2. **`MirrorsProducerWindow`** — rejected round 2: it *moves* the assumption rather than removing it.
   A candidate holding only the newest surviving block is a valid trailing suffix, so accidental loss
   of every older block passes. And non-empty → empty has no honest rule at all: a missing source and
   an expired window are indistinguishable, while refusing empty candidates wedges a quiet user.

**Measured:** blocks returns 148 rows over ~35 days; `--since` **is** honored (19 rows from
`20260801`), yet `--since 20251211` returns the same 148 from 2026-07-01, while `all-daily` returns
190 back to 2025-12-11 over the identical corpus. That proves truncation **exists**. It does **not**
prove any particular recession is producer-authorized — establishing that needs two observations
separated in time, which no single planning session can produce. **I made exactly that substitution
and the review caught it**: the project's recurring defect class (b), proving one property and using
another.

The only remaining in-ticket option, `NoDisappearance` for blocks, wedges the store the first time
the window legitimately slides — which the measurement says it will — with no useful escape.
Accepting bounded trailing loss is the honest answer, and it is not a planner's to accept.

## What would unpark it

**ISS-090** answered — ratify the `hourly --cached` behavioral change, cut the surface, or accept
~100-minute refreshes.

**AND ISS-091** answered. Corrected after the disposition review, which found my first unpark
condition still too weak: **passive longitudinal observation is not authorization.** T-012 watching
repeated transitions can show that blocks *receded*; it cannot distinguish authorized producer
eviction from accidental source loss, so it does not satisfy L-006 on its own. It is diagnostic
evidence, not a premise. Only three honest premises exist:

1. **Producer-supplied window/retention metadata bound to each response** — the only one that makes
   mirroring safe by construction, and ccusage does not expose it today.
2. **A controlled experiment establishing the pinned producer's eviction contract** — i.e.
   deliberately constructing a corpus and observing what the pinned ccusage version drops, which is a
   real experiment someone can run, not a passive wait.
3. **An explicit owner decision accepting bounded trailing loss** — recorded as accepted rather than
   discovered.

T-012 may still collect the transitions; that is worth doing, but it is input to (2), not a
substitute for it.

**Items 2 (`readGeneration`) and 5 (the `ccusageInvokedAt` rename) are independently shippable** if
the owner wants a split ticket. **Item 1's two new checks are not** — both depend on the registry and
SnapshotPayloadV1, which are exactly what is blocked.
